## 十一、地块系统（v2：全球方格 + 城市加密）

**地块 = UTM 公里方格。** 全世界只有一套方格：乡村一格，城市按规模加密成多格。
零烘焙、零几何数据、按需生成，所以"用更低的内存铺满全世界的城市"这件事才成立。

### 1. 为什么推倒 v1

v1 契约（每城一份 GeoJSON、按行政区 / 主干道切分）有三个硬伤：

| 问题 | 后果 |
| --- | --- |
| **数据从哪来** | 行政区面与主干道只有区域包里才有（富尔达 z13）。全球底图只到 z6，99% 的城市拿不到切分数据，v1 的"走到哪打到哪"根本走不出去 |
| **体积** | 全世界建成区约 1.5M km²，1 km 格就是 1.5M 格；按 200k 城镇各切 30 格算 6M 格，每格 100–150 B，**几百 MB 起步**，且每加一座城都要重烘 |
| **不可复现** | 切分用简化后的矢量瓦片，同一城市在不同缩放 / 不同版本可能切出不同结果，存档对不上号 |

关键判断：**地块的职责是"可占领的格子"，不是"照抄城市轮廓"**。轮廓是底图的事；
地块只要满足四条——铺满全图、大小随城市规模变、任何城市都算得出来、存档可复现。

### 2. 方格（唯一地基）

| 项 | 取值 |
| --- | --- |
| 坐标系 | UTM（WGS84，k0=0.9996），与右上角格网同一套算法：`core/geo.ts` 的 `utmOf` / `utmToLonLat` |
| 层级 | 8 km → 4 → 2 → 1 km，逐级四叉，每级是上一级的等分 |
| 一格 | 边长 s 的 UTM 方格，四角反算成经纬度（1 km 格曲率 < 0.1 m，四角足够） |
| 格号 | `32U/1000/547000/5600000`；人读 `32U 547 5600`，**就是地图格网的读数** |
| 极区 | `|lat| > 84` 不做地块（UPS 不在范围内） |

为什么不用墨卡托 z 瓦片：墨卡托方格随纬度缩水（50°N 只有赤道的 64%），而且会和游戏里
已经画出来的 UTM 格网错开一个角；UTM 方格**就是**那张格网，一格 = 图上的一格。

### 3. 加密规则（乡村一格，城市多格）

先要一个"哪里是城市"的场：`urban(lon, lat)` = 是否落在某城镇圆盘内。

- 半径 `r = clamp(8·√pop, 400 m, 40 km)`（按 5000 人/km² 反推；都市圈人口会偏大，用上限截住）。
- **分裂**：8 km 根格若城市覆盖率 ≥ 16% 且边长 > 1 km，切成 4 个 4 km；子格继续判、继续切。
- **覆盖率**：格内 5×5 采样，25 个点里落在任一城镇圆盘内的比例。
- **预算**：单视口最多 420 格，按 `覆盖率 × 面积` 从高到低切——城市中心先细，边缘自动粗。
- 半径 < 1.2 km 的居民点（村庄）不参与分裂：**乡村就是一个 8 km 地块**。

| 场景 | 格数 | 边长 | 实测耗时 |
| --- | --- | --- | --- |
| 乡村（无城市圆盘） | 1 | 8 km | < 0.2 ms |
| 小镇（富尔达 7 万） | 56 | 1–4 km | 4.4 ms |
| 大城市（柏林 370 万） | 258 | 1 km | 2.1 ms |
| 特大城市（上海） | 420（预算上限） | 2 km 为主 | 1.5 ms |

**"城市由多个地块组合"** 就落在这张表上：城市大小决定触及几个 8 km 根格、每个根格降到哪一级。

### 4. 数据：一条城镇记录，一格不多

`app/public/data/cities.json`（全局）+ `cities_<区域>.json`（区域叠加，按 `index.json` 的 key）。

| 字段 | 字节 | 说明 |
| --- | --- | --- |
| 经度 / 纬度 | 4 + 4 | Float32（≈ 1 m） |
| 半径 | 1 | 200 m 为单位 |
| 类型 | 1 | 1 = 市，2 = 镇 |

- 全球：`Tools/bake_cities.mjs` 从世界包 z6 的 `places` 点解出 **5,615 座城镇 / 73 KB**。
- 区域：从富尔达包 z13 解出 bbox 内 **1,623 个居民点 / 18 KB**（含村庄，村庄只当"这里有人"用）。
- **地块几何：0 B。** 运行时由（格网 + 圆盘）现算，单视口 ≤ 420 格 / ≤ 20 KB，离开视口即丢。

省下来的量级：按 v1 烘焙全世界是 **几百 MB 到 GB**，现在是 **73 KB + 0**。

### 5. 运行时结构

| 层 | 文件 | 职责 |
| --- | --- | --- |
| 规则 | `core/cells.ts` | `cellsInView(bounds, near, budget)`、`cellAt/cellRing/cellId/cellLabel`；常量 `BASE_STEP 8000` / `MIN_STEP 1000` / `SPLIT_COVER 0.16` / `CELL_BUDGET 420` |
| 数据 | `data/cities.ts` | base64 二进制解析 + 0.5° 桶索引，`near(bbox)` 只扫相关桶 |
| 呈现 | `map/cellLayer.ts` | GeoJSON source `cells`（`promoteId: 'id'`）+ 4 层：fill / line / edge / hover；`moveend` 防抖 240 ms 重算 |
| 状态 | `data/cellStore.ts` | `localStorage['cells.owner.v1'] = { owners: { '32U/1000/547000/5600000': 'nato' } }` |

归属**不写进几何**，只按格号存在 feature-state 与存档里；几何每次都可以重算，重算结果与上次逐字节一致。

### 6. 占用规则（沿用 v1 的判断，去掉几何依赖）

1. 一个单位同一时刻只占一格；一格同一时刻只有一个占领方。
2. 单位进格 → `owner` = 单位阵营，并刷新邻居格的可进入状态。
3. 单位离开 → 该格回到 `null`，不做"遗留控制"。
4. 敌我不能共占一格；进入敌方格 = 攻击，解算结果决定归属。
5. 邻接不存表：同边长 8 邻域由 `(e±s, n±s)` 直接算；跨级邻接沿边中点向外探一个点、反查所在格
   （`cellAt`），天然处理"一个 8 km 邻居对四个 1 km 格"。

### 7. 视觉克制

| 元素 | 参数 |
| --- | --- |
| 未占领 | 不填充；边界 `#7d7566`，0.9–1.5 px，alpha 0.20 → 0.13（z11.5 → 15） |
| 我方 / 敌方 | 填充 alpha 0.15 纯色；边界 1–1.6 px，alpha 0.55 |
| 悬停 | 白描边 2.2 px，alpha 0.85 |
| 显示层级 | `minzoom 11.5`；低于 11.5 不生成也不画 |
| 禁止 | 渐变、发光、阴影、遮挡地名 |

1 km 格在 z14（约 6 m/px）是 166 px，街道与建筑仍然清晰——这是 v1 的出口条件，v2 已达成。

### 8. 操作

- 顶部工具条「地块」：开关整层；
- 单击格子 = 用当前阵营（兵牌面板选的那一侧）占领，再点同一格 = 取消，Shift+单击 = 清除；
- 左上角面板：本视口格数 / 城市格数 / 最细边长 / 生成耗时；悬停显示格号、面积、乡村还是城市格。

### 9. 分期

| 期 | 内容 | 出口条件 |
| --- | --- | --- |
| 1 | 方格生成 + 归属着色 + 手动切换 | 富尔达能看到格子被染成蓝 / 红，街道仍清晰（**已完成**） |
| 2 | 兵牌进出驱动归属 | 拖动兵牌，格子跟着变色 |
| 3 | 邻接移动约束 + 冲突解算 | 能打完一场巷战 |
| 4 | 区域包逐个补 `cities_<key>.json` | 走到哪座城市都能打 |

### 10. 明确不做

- **不做"照轮廓切多边形"**（行政区划 / 主干道切割）：数据依赖、体积、不可复现，三样都不划算。
  将来若要更好看，只做"格边贴着街区描一遍"的**装饰**，不改规则。
- 不做控制度累积、士气、补给：一格只有一个占用者。
- 不做六角格。
